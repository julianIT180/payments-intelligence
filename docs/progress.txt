## Systemaufbau

### Workflow 1: Payments Intelligence – On-Demand Brief (Unterworkflow)

```
On form submission  ODER  Called by Monitor (Sub-Workflow-Trigger)
                    |
            Build Search Query
            /                \
   Tavily Search          Feed List
        |                     |
Normalize Tavily         Fetch Feeds
        |                     |
        |                 Parse XML
        |                     |
        |          Normalize Feed Items
        |                     |
        |          Fetch Article Pages (Volltext)
        |                     |
        |          Extract Article Text
        \                    /
         Combine Sources (append)
                    |
         Triage Relevance (Haiku 4.5)
                    |
         Clean and Rank Sources
                    |
         Extract Metadata (Haiku 4.5 + Structured Output Parser)
                    |
         Analyse and Draft Brief (Sonnet 5)
                    |
            Assemble Brief  (setzt model_refused)
                    |
       Prepare DB Record (Hash + Publikations-Gate)
                    |
       Persist Brief?  --persist-->  Insert Brief -> Insert Sources -> Return Result
                       --skip------------------------------------->  Return Result
```

### Workflow 2: Daily Payments Monitor
Schedule (alle 2 Tage, 08:00) -> Watchlist (5 Themen) -> Loop -> Sub-Workflow -> Pause 5 s
done-Ausgang -> Run Summary

### Workflow 3: Weekly Payments Report
Schedule (Montag 08:00) -> Fetch Week Data (SQL, 7 Tage) -> Group by Category
-> Synthesise Report (Sonnet 4.6) -> Build HTML -> Save Report -> Send via Resend

### Frontend
Next.js (App Router, JS statt TS, Tailwind) auf Vercel, liest Supabase per anon/publishable Key.
Seiten: Feed (/), Brief-Detail (/brief/[id]), Companies, Reports, About.

## Phase 3 — Strukturierte Ausgabe (25.08.)

Zweiter LLM-Zweig, Haiku statt Sonnet (halber Preis fuer simple Extraktion).
Structured Output Parser, festes Vokabular fuer category und relevance-Felder —
sonst erfindet das Modell bei jedem Lauf neue Kategorien.

### Architektur-Lernpunkt: Reihenfolge in n8n
Parallele Zweige in Assemble Brief -> Node lief zweimal.
"Execute Once" loest das NICHT (begrenzt Items, nicht Ausfuehrungen).
Verbindung getrennt -> ExpressionError "Node hasn't been executed".

Regel: $json = vorheriger Node. $('X') = beliebiger Node, der VORHER lief.
Die Verkabelung bestimmt die Ausfuehrungsreihenfolge.

### Extraktion ist zu grosszuegig
primary_companies enthielt 7 Firmen, davon 6 aus themenfremden Quellen.
Sonnet ignoriert irrelevante Quellen, Haiku bei reiner Extraktion nicht.
Muster: Extraktionsmodelle sind zu grosszuegig, Analysemodelle zu wortreich.

## Phase 2.4 — Volltext-Extraktion RSS (25.08.)

EZB-Feeds liefern nur Ueberschriften -> confidence lag bei 48.
HTTP Request pro Link + Extraktion:
- mainRegion() isoliert article/main/body (ECB-Seiten: 60 KB Navigation vorher)
- keepProse() behaelt nur Zeilen mit >60 Zeichen, Satzzeichen,
  <60 % Grossbuchstaben-Woerter
- Unter 200 Zeichen -> ehrlich auf Headline-Only zurueckfallen

Ergebnis: confidence 48 -> 72, impact 72 -> 78. Der Brief zitiert seitdem
konkrete Zahlen (92 % Bargeldakzeptanz, Mobile 36 % -> 68 %).

## Phase 4 — Datenbank (26.08.)

### Supabase statt Google Sheets
Sheets braucht Google-Cloud-Projekt + OAuth (~20 Schritte), Supabase nur
Registrierung. Migration waere ohnehin noetig (Website liest Postgres).
Echtes SQL erlaubt Dedup per UNIQUE-Constraint.

### Konfiguration
- Region Frankfurt (DSGVO)
- "Automatically expose new tables" AUS, "automatic RLS" EIN
- Session Pooler, Port 5432, SSL Require
- Ignore SSL Issues EIN noetig (self-signed Intermediate am Pooler).
  TLS bleibt aktiv, nur Kettenpruefung entfaellt.
- Max Connections 100 -> 5

### Dedup-Hash
Thema + sortierte kanonische Quellen-URLs, NICHT der Brieftext.
Der LLM-Text unterscheidet sich bei jedem Lauf minimal.
.sort() noetig, weil Suchmaschinen keine stabile Reihenfolge liefern.

### Bug: on conflict do nothing liefert keine ID
Insert Brief gab nur {"success": true}, Insert Sources schrieb null in not-null.
Fix: on conflict do update set topic = excluded.topic
     returning id, ..., (xmax = 0) as was_inserted

### SQL-Injection
Alle Writes parametrisiert ($1, $2, ...). Wert getrennt vom Befehl uebertragen.

## Phase 5 — Scheduler (26.08.)

### Sub-Workflow statt Nachbau
Bestehender Workflow bekam zweiten Trigger. Ein Ort fuer die Logik.
Execute Sub-workflow auf "Run once for each item" — sonst landen alle
Themen in EINEM Aufruf und Build Search Query nimmt nur $input.first().

### Fehlertoleranz
On Error: Continue am Sub-Workflow-Node. Bei 5 Themen = 15 API-Aufrufe.
Scheitert Thema 3, wuerde "Stop Workflow" auch 4 und 5 verhindern.

### Kalibrierungsfehler
Erst MIN_SOURCES = 3 UND MIN_CONFIDENCE = 35.
Stripe verworfen mit "2 Quellen, confidence 55" — Confidence lag ueber der
Grenze, es scheiterte an der Quellenzahl. Zwei gute Quellen sind mehr wert
als fuenf schwache.
Damals geplant: MIN_CONFIDENCE = 40, Quellenuntergrenze lockern.
Tatsaechlich blieb der Export lange bei 3 / 35. Vereinheitlicht am 27.08.
(siehe "Publikations-Gate vereinheitlicht" unten).

### Zeitfenster
'week' ergab bei Einzelunternehmen 1 Quelle und Briefs ueber Stellenanzeigen.
Auf 'month' umgestellt — Duplikate faengt der Hash ab.

### Referenzlauf 26.08., 5 Themen
5 verarbeitet, 4 neu, 1 zu schwach, 13 Quellen.
[78/72] digital euro, [68/55] agentic payments, [62/55] Visa, [35/45] Adyen.
Ranking sortiert korrekt.

### Betrieb

## Publikations-Gate vereinheitlicht (27.08.)

Zwei Verweigerungen, klar getrennt.

Modellseitig (Analyse-Prompt, Regel 4): bei < 3 Quellen oder Quellen ohne
Themenbezug antwortet Sonnet nur mit "INSUFFICIENT EVIDENCE — ...".
Assemble Brief erkennt den fuehrenden Grossbuchstaben-Marker und setzt den
strikten Boolean model_refused.

Publikationsrichtlinie (Prepare DB Record): speichern nur, wenn ALLE gelten —
model_refused === false, had_enough_evidence === true, source_count >= 3,
confidence_score >= 40. Sonst { skipped: true }.

Neuer IF-Node "Persist Brief?" prueft "skipped is false":
  TRUE  -> Insert Brief -> Insert Sources -> Return Result
  FALSE -> Return Result

Uebersprungene Laeufe erreichen Insert Brief / Insert Sources nicht mehr.
Vorher lief der Skip-Sentinel durch Insert Brief, loeste eine NOT-NULL-
Verletzung aus und wurde nur von onError = continueRegularOutput aufgefangen.

MIN_CONFIDENCE 35 -> 40. Persist-Pfad gibt jetzt explizit skipped: false zurueck.
Kein Schema-, Modell- oder Retrieval-Wechsel am Gate selbst.

## Metadaten-Extraktion robust gemacht (27.08.)

Live-Test 1 brach in "Extract Metadata" / Structured Output Parser ab:
"Model output doesn't fit required format".

Ursache: Der Parser war aus einem JSON-Beispiel generiert ("Generate From
JSON Example"). Jedes Feld im Beispiel wird dadurch als PFLICHT mit
konkretem Typ (String / Zahl / Array) erzwungen. Der Prompt sagt aber
"wenn ein Feld nicht belegbar ist, null zurueckgeben". Bei duenner Evidenz
liefert Haiku also null fuer headline/summary etc. -> Schema lehnt null ab
-> Pipeline crasht VOR dem Analyse-Schritt. Der Lauf konnte gar nicht bis
zu einem ehrlichen INSUFFICIENT EVIDENCE kommen.

Fix, ohne Qualitaet zu senken und ohne Fehler zu verstecken:
- Parser auf "Define Below" (explizites JSON Schema) umgestellt.
  Beschreibende Textfelder: type ["string","null"] (null erlaubt).
  Listen: array of string, [] erlaubt, nie erfunden.
  impact_score / confidence_score: Pflicht, Zahl 0-100, nie null.
  category: Pflicht-String; Vokabular inkl. "other"-Fallback im Prompt.
- Extract-Metadata-Prompt praezisiert: null/[]/niedrige Zahl sind ehrliche
  Antworten bei duenner Evidenz; Scores immer als Zahl; genau ein
  JSON-Objekt, keine Code-Fences, kein Text drumherum.
- Kein Auto-Fixing-Format, kein On-Error/Continue. Echte Formatfehler
  brechen weiterhin sichtbar ab.

Downstream unveraendert: Assemble Brief (meta = rawMeta.output || rawMeta),
Prepare DB Record (str()/num()/arr() vertragen null/[] bereits). DB-Spalten
headline/summary/category/... sind ohnehin nullable -> kein Schema-Wechsel.
